# 0005 — Pin the specta release candidates exactly

- Status: accepted
- Date: 2026-09-24
- Spec: refines §4 IPC contract

## Context
The whole IPC contract is generated by `specta`, `specta-typescript` and `tauri-specta` (ADR 0003). There is no stable 2.x: the only versions that work with Tauri 2 are release candidates, currently `2.0.0-rc.25`. Cargo reads a bare `"2.0.0-rc.25"` as a caret requirement, so a fresh resolve (a new contributor, a CI runner without the lockfile, `cargo update`) may pick up `rc.26`. An rc bump is allowed to break its API, and the three crates only work in matched versions. A silent bump would either fail to build or — worse — change the generated TypeScript, which makes the ADR 0003 freshness check fail on a file nobody touched.

## Options considered
1. Caret requirement, the cargo default — picks up rc fixes automatically; an unrelated PR can go red because an rc changed the generator's output, and the three crates can drift out of lockstep.
2. Exact `=` pin, which tauri-specta's own docs require — bumps become deliberate, reviewable commits; nobody gets rc fixes for free, and the pin has to be maintained by hand.

Waiting for a stable 2.0 was not an option: Phase 0 needs the IPC contract now, and specta 1 does not support Tauri 2.

## Decision
Option 2. All three crates are pinned with `=` in `[workspace.dependencies]` and bumped together in one commit that also re-runs `pnpm gen:types`, so any change to the generated bindings is visible in the same diff as the version bump.

## Consequences
Dependabot-style automation cannot bump these three; someone must do it deliberately and re-generate in the same commit. `Cargo.lock` alone is not enough, because it does not constrain a fresh resolve that ignores it. Revisit when specta and tauri-specta 2.0 ship stable: the pin can then relax to a caret requirement and this ADR is superseded.
